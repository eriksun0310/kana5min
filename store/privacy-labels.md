# 隱私營養標籤（Apple）與資料安全性（Google Play）建議填法

依實際使用的 SDK：`react-native-google-mobile-ads`（AdMob，只用獎勵廣告，請求固定非個人化）與 `react-native-purchases`（RevenueCat）。**沒有使用 ATT／`expo-tracking-transparency`**，沒有分析或追蹤 SDK，沒有帳號系統，學習紀錄只存在本機。app.json 的 `ios.privacyManifests` 已設 `NSPrivacyTracking: false`、`NSPrivacyTrackingDomains: []`。

資料類型與「皆不用於追蹤」與兩個後台已填的答案一致；各類型的「用途」「連結到使用者身分」細項是依 SDK 行為整理的建議，若與後台不同以後台為準（2026-10-27／28 後台狀態見 PROGRESS.md「商店後台設定進度」）。若日後新增 SDK 或改成個人化廣告，要同步改這裡、後台、隱私權政策與 ATT 設定。

## Apple：App 隱私（已發佈）

- 是否蒐集資料：**是**
- 是否用於追蹤：**否**（所有資料類型皆不用於追蹤；不連結到使用者以外的追蹤用途）

| 資料類型 | 用途 | 連結到使用者身分 | 用於追蹤 |
|---|---|---|---|
| 裝置識別碼（Device ID） | App 功能、第三方廣告 | 是（RevenueCat 匿名 ID、廣告識別碼） | 否 |
| 購買記錄（Purchases） | App 功能 | 是 | 否 |
| 產品互動（Product Interaction） | 第三方廣告、App 功能 | 否 | 否 |
| 廣告資料（Advertising Data） | 第三方廣告 | 否 | 否 |
| 當機資料（Crash Data） | App 功能 | 否 | 否 |
| 效能資料（Performance Data） | App 功能 | 否 | 否 |

不蒐集：聯絡資訊、健康與健身、財務資訊（付款由 Apple 處理）、位置、敏感資訊、聯絡人、使用者內容、瀏覽記錄、搜尋記錄、診斷以外的其他資料。

注意：因為沒有 ATT 提示，也不使用於追蹤，Info.plist 不需要 `NSUserTrackingUsageDescription`。

## Google Play：資料安全性（已儲存）

- 是否蒐集或分享必要的使用者資料類型：**是**；後台摘要為「收集或分享 4 種資料」（購買記錄屬「財務資訊」、應用程式互動屬「應用程式活動」、當機／診斷／其他效能屬「應用程式資訊與成效」、裝置 ID 屬「裝置或其他 ID」，共 4 大類、6 個項目）
- 所有資料在傳輸過程中加密：**是**
- 使用者可要求刪除資料：不適用（沒有帳號；本機資料刪除 App 即清除）
- 不允許建立帳戶；已申報含廣告

| 資料類型 | 收集／分享 | 用途 | 是否必要 |
|---|---|---|---|
| 購買記錄（財務資訊） | 收集 | App 功能 | 必要 |
| 裝置或其他 ID | 收集＋分享（AdMob、RevenueCat） | App 功能、廣告或行銷 | 必要 |
| 應用程式互動（應用程式活動） | 收集＋分享 | 數據分析（含功能） | 必要 |
| 當機記錄、診斷、其他效能資料（應用程式資訊與成效） | 收集＋分享 | 數據分析（含功能） | 必要 |

Google 的申報比 Apple 保守（把 SDK 資料視為「分享」），兩者方向一致、都沒有用於追蹤。

- 廣告 ID 權限：宣告使用（用途＝廣告或行銷）。
- 目標對象：13 歲以上，非兒童導向。
